📈 2. Scaling Law · 무엇을 얼마나 키울 것인가?

모델·데이터·계산량을 키우면 평균 손실이 예측 가능한 경향으로 감소하지만, 예산 안에서 세 요소의 균형이 중요합니다.

모델만 크게 만들고 데이터를 충분히 보여주지 않으면 under-trained가 될 수 있습니다. Chinchilla 연구는 같은 계산 예산에서 모델과 토큰을 함께 배분하는 compute-optimal 관점을 강조했습니다.

오해 금지: Scaling Law는 “크게 만들면 무조건 모든 능력이 안전하게 좋아진다”는 법칙이 아닙니다. 평균 예측 손실의 경향과 실제 사실성·안전성·특정 업무 성능은 별도로 평가해야 합니다.

GPU의 HBM은 크지만 상대적으로 느리고, SRAM은 작지만 빠릅니다. Attention 중간 행렬을 HBM에 반복 저장·읽는 IO가 병목이 됩니다.

역설: Backward에서 일부 값을 저장하지 않고 다시 계산하면 FLOPs는 조금 늘 수 있지만 HBM 왕복이 크게 줄어 실제 실행 시간은 더 짧아질 수 있습니다. 연산량과 실행시간은 같은 말이 아닙니다.

왜 Low-Rank인가?

업무 적응에 필요한 가중치 변화가 원래 거대 행렬의 모든 자유도를 요구하지 않는다고 가정합니다. 작은 r이면 학습 파라미터·Optimizer state·저장 용량이 크게 줄어듭니다.

🧯 자주 헷갈리는 개념

Pretraining과 SFT는 모두 다음 토큰 예측인데 무엇이 다른가?

손실 형태는 비슷할 수 있지만 데이터와 목적이 다릅니다. Pretraining은 방대한 원문에서 일반 패턴을 배우고, SFT는 입력-원하는 응답 쌍으로 행동을 조정합니다.

Data Parallelism과 Model Parallelism은 같은가?

아닙니다. Data Parallelism은 모델을 복제하고 데이터를 나누며, Model Parallelism은 한 모델의 계산·파라미터 자체를 여러 장치에 나눕니다.

FlashAttention은 Sparse Attention인가?

아닙니다. 기본 FlashAttention은 정확한 dense attention 결과를 유지하면서 IO와 메모리 접근 방식을 개선합니다.

BF16은 FP16보다 bit가 많은가?

둘 다 16-bit지만 배치가 다릅니다. BF16은 exponent가 8-bit라 FP32와 비슷한 범위를 갖고 mantissa가 짧아 정밀도는 낮습니다.

LoRA와 QLoRA는 모델을 작게 만드는 압축 모델인가?

LoRA는 학습 가능한 변화량을 low-rank로 제한하는 튜닝법입니다. QLoRA는 여기에 frozen base weight의 양자화를 결합해 학습 VRAM을 줄입니다.

Fine-tuning하면 회사 최신 지식이 영구적으로 정확해지는가?

보장되지 않습니다. 사실 업데이트·출처·권한 관리가 중요한 지식은 RAG가 더 적절할 수 있고, Fine-tuning은 행동·스타일·과제 적응에 주로 사용합니다.

✅ 연결 확인 퀴즈

Q1. Chinchilla 관점에서 모델 크기만 늘리면 왜 비효율적일 수 있나?

고정된 계산 예산에서 모델에 비해 학습 토큰이 부족하면 큰 모델이 충분히 학습되지 않을 수 있기 때문입니다.

Q2. ZeRO-1·2·3의 차이를 한 줄로 말하면?

GPU 사이에서 분할하는 대상을 Optimizer state → Gradient → Parameter 순으로 단계적으로 늘립니다.

Q3. FlashAttention이 FLOPs를 조금 더 쓰면서도 빨라질 수 있는 이유는?

비싼 HBM 읽기·쓰기를 줄이고 빠른 SRAM에서 block 계산하며, 저장 대신 일부 재계산하는 편이 실제 하드웨어에서 더 빠를 수 있기 때문입니다.

Q4. LoRA의 W = W₀ + BA에서 무엇을 학습하나?

기존 W₀는 고정하고 작은 low-rank 행렬 A와 B를 학습합니다.

Q5. QLoRA에서 양자화되는 것과 학습되는 것은?

Frozen base weight W₀는 주로 4-bit로 저장되고, LoRA Adapter A·B가 학습됩니다. 실제 계산 시에는 필요한 정밀도로 변환됩니다.
