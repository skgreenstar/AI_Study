📍 1. Attention에게 ‘순서’를 알려주기

Self-Attention은 토큰을 한꺼번에 비교하므로, 별도 위치정보가 없으면 “개가 사람을 물었다”와 “사람이 개를 물었다”의 순서를 구별하기 어렵습니다.

🪟 3. Attention을 더 길고 빠르게

모든 토큰 쌍을 비교하는 Full Attention은 길이 n에 대해 비교칸이 n²으로 늘어납니다.

Full Attention · 모두가 모두를 봄

계산·메모리 규모 ≈ O(n²)

Sliding Window · 가까운 이웃 중심

각 토큰이 주변 창만 보며, 층을 쌓을수록 CNN의 receptive field처럼 간접적으로 더 넓은 범위를 봅니다. Longformer는 일부 global token으로 먼 구간도 연결합니다.

🏗️ 4. Transformer 모델은 세 가족

목표가 “이해·분류”인지 “생성”인지 “입력을 다른 출력으로 변환”하는지에 따라 구조가 달라집니다.

Encoder–Decoder

T5 계열

입력을 양방향으로 이해
출력을 왼쪽부터 생성

잘 맞는 일: 번역, 요약, text-to-text 변환

Encoder-only

BERT 계열

왼쪽 ↔ 오른쪽 문맥 이해
분류·추출 Head

잘 맞는 일: 분류, 검색 임베딩, NER, 추출형 QA

Decoder-only

GPT 계열

이전 토큰만 보고 다음 토큰 생성
반복 생성

잘 맞는 일: 글·코드 생성, 대화, 범용 LLM

중요: Encoder-only의 양방향은 한 문장의 양쪽 문맥을 동시에 참고한다는 뜻입니다. Decoder-only의 causal mask는 미래 정답 토큰을 미리 보지 못하게 가립니다.

🧯 자주 헷갈리는 지점

Position Embedding과 Token Embedding은 같은가?

아닙니다. Token Embedding은 토큰의 의미 좌표, Position 정보는 순서 좌표입니다. 둘을 결합해야 “무엇이 몇 번째에 있는가”를 압니다.

LayerNorm은 BatchNorm과 같은가?

아닙니다. LayerNorm은 각 샘플·토큰의 feature 차원 내부를 정규화하므로 배치 크기에 덜 의존합니다. Transformer에 잘 맞는 이유입니다.

GQA와 Sliding Window Attention은 같은 최적화인가?

아닙니다. GQA는 Head 사이 K·V 공유를 늘려 KV cache를 줄이고, Sliding Window는 토큰이 참고하는 위치 범위를 줄입니다.

BERT도 다음 토큰을 생성할 수 있나?

기본 BERT는 Encoder-only·MLM 구조라 자연스러운 순차 생성에 맞지 않습니다. 문맥 이해, 분류, 추출, 임베딩에 더 적합합니다.

RoBERTa는 완전히 다른 구조인가?

핵심 Transformer Encoder 구조는 거의 같고, BERT의 사전학습 데이터와 절차를 더 강하게 최적화한 모델입니다.

✅ 연결 확인 퀴즈

Q1. Attention에 위치정보가 필요한 가장 근본적인 이유는?

기본 Self-Attention은 토큰 쌍의 관련성을 계산하지만 입력 순서 자체를 자동으로 구별하지 못하기 때문입니다.

Q2. RoPE가 Q와 K를 회전시키는 이유는?

회전된 두 벡터의 내적에 절대 위치가 아니라 위치 차이, 즉 상대 거리 정보가 자연스럽게 들어가게 하기 위해서입니다.

Q3. Pre-Norm의 핵심 이점은?

Attention·FFN에 들어가기 전 신호 규모를 정리해 Residual 경로와 gradient가 깊은 층을 더 안정적으로 통과하도록 돕습니다.

Q4. BERT의 MLM에서 선택된 토큰을 전부 [MASK]로 바꾸지 않는 이유는?

사전학습 때만 존재하는 [MASK]에 과도하게 의존하지 않고 실제 입력에서도 견고하게 문맥을 표현하도록 하기 위해서입니다.

Q5. DistilBERT와 RoBERTa의 목적 차이는?

DistilBERT는 지식 증류로 속도·크기를 개선하고, RoBERTa는 같은 계열 구조의 학습 절차와 데이터 사용을 강화해 성능을 높입니다.
