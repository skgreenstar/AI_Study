에이전틱 LLM

학습이 끝난 LLM은 아는 것이 고정되어 있고 아무 행동도 못 합니다. 가중치를 건드리지 않고 바깥에서 이 둘을 메우는 세 단계 — 찾아보기(RAG), 도구 쓰기, 스스로 반복하기(에이전트) — 를 봅니다.

이 장을 마치면RAG의 검색을 후보 추출과 재순위로 나눠 설명할 수 있다
이 장을 마치면도구 호출의 3단계에서 LLM이 하는 일을 구분할 수 있다
이 장을 마치면ReAct 루프를 예시로 따라갈 수 있다
큰 그림비유핵심 개념수식 해부활용 사례오해퀴즈연결

다음 조각 · 8장

찾고 실행했다고 끝이 아니다. 검색·답변·행동을 각각 어떻게 평가할까?

  1. 1. 근거를 찾아 입력에 붙인다

    왜 필요한가 모델 내부를 다시 학습하지 않고 이번 질문의 참고 자료를 보충한다.

  2. 2. 넓게 찾고 다시 정렬한다

    왜 필요한가 빠른 후보 수집과 정밀한 순서 매기기는 비용·목적이 다르다.

  3. 3. 외부 프로그램으로 일을 수행한다

    왜 필요한가 LLM이 함수 이름과 인자를 제안하면 프로그램이 실제로 실행한다.

  4. 4. 결과를 보고 다음 행동을 고른다

    왜 필요한가 고정된 단계만 실행하는 흐름과 달리 관찰에 따라 반복·중단을 결정한다.

화살표는 이해를 위한 연결입니다. 모두를 반드시 순서대로 적용하는 시스템 구성도는 아닙니다.

RAG가 필요한 이유 네 가지. 지식이 사전학습 데이터에 갇혀 있다 · 컨텍스트 크기에 한계가 있다 · 쓸모없는 정보가 섞이면 LLM이 산만해진다 · 요금이 입출력 토큰 단위다. 즉 "전부 넣기"가 아니라 "필요한 것만 넣기"가 답입니다.

사서가 먼저 책을 추려 준다

암기한 것만으로 답하는 대신, 사서가 서가 전체에서 관련 있어 보이는 책 50권을 빠르게 꺼내고(후보 추출), 그중 정말 쓸 만한 5쪽을 꼼꼼히 골라(재순위) 책상에 올려 줍니다. 신입은 그 5쪽을 읽고 답을 씁니다.

한계. 사서가 엉뚱한 쪽을 주면 신입은 그럴듯한 오답을 씁니다. 답의 품질은 검색 품질을 넘지 못합니다.
도구와 에이전트

전화기와 업무 권한

도구 호출은 신입에게 사내 전화번호부를 주는 것입니다. 신입은 "누구에게 무엇을 물을지"만 적고, 실제 통화는 비서(백엔드)가 한 뒤 결과를 전해 줍니다. 에이전트는 "문제가 풀릴 때까지 알아서 확인하고, 계획하고, 조치하라"는 위임입니다.

한계. 권한을 준 만큼 실수의 결과도 현실에 닿습니다. 메일을 잘못 보내거나 데이터를 밖으로 내보낼 수 있습니다.

보충 ④

검색을 돕는 두 확장

가짜 문서 만들기 (HyDE). 질문과 문서는 글의 성격이 다릅니다. LLM에게 먼저 가상의 답 문서를 쓰게 하고("Cuddly is in…"), 그 가짜 문서의 임베딩으로 검색합니다.

조각에 맥락 붙이기 (Contextual Retrieval). 조각만 떼어 놓으면 "그는"이 누구인지 모릅니다. 문서 전체와 조각을 LLM에 주고 "이 조각이 문서에서 어떤 위치인지 짧게 설명하라"고 해 그 설명을 조각 앞에 붙입니다. 같은 문서를 반복해 넣으므로 프롬프트 캐싱으로 비용을 줄입니다.

해 보고 결과를 보고 다음 결정 — ReAct = 판단 → 행동 → 결과 관찰을 반복하기

에이전트: 사용자를 대신해 자율적으로 목표를 추구하고 과제를 완수하는 시스템. ReAct = Reason + Act.

단계예: "곰 인형이 추워해요. 뭔가 해 주세요."
관찰곰이 추운 것은 방 온도 때문일 수 있는데, 현재 온도를 모른다.
계획방 온도를 확인한다.
행동get_current_room_temperature() → 65°F
관찰평균보다 5°F 낮다. 온도를 올려야 한다.
계획 → 행동increase_temperature(value=5)
관찰 → 출력"온도를 70°F로 맞췄어요. 곧 따뜻해질 거예요."

확장 ⑧

A2A와 안전

A2A(Agent2Agent, Google 2025): 에이전트끼리 대화하는 표준. 온도 조절·재실 감지·공기질·에너지 관리 에이전트가 서로 협력해야 할 때 씁니다. 에이전트는 자신의 카드(이름, 주소, 버전, 할 수 있는 기술 목록)를 공개하고, 실행기가 요청을 처리합니다. MCP가 "에이전트 ↔ 도구"라면 A2A는 "에이전트 ↔ 에이전트".

안전. 현실 세계에 해를 끼칠 수 있습니다(예: 데이터 유출). 대응: 학습 단계의 정렬, 추론 시 안전장치, Agent-SafetyBench 같은 벤치마크.
강의의 맺음말. 환각은 큰 문제다 · 추론 능력이 병목이다 · 평가가 어렵다 · 단순하게 시작해 점차 키워라 · 유능한 모델로 시작해 나중에 크기를 줄여라 · 투명성과 관찰 가능성이 신뢰와 디버깅을 돕는다.

최소 수식 해부

검색 품질을 재는 네 지표. 같은 예시로 계산합니다: 관련 조각이 전체에 3개 있고, 상위 4개 결과의 관련 여부가 [✗, ✓, ✓, ✗].

수식 1·2

Precision@k와 Recall@k

한 문장으로정밀도 = 가져온 것 중 맞는 비율, 재현율 = 필요한 것 중 찾은 비율

작은 예 관련 문서가 총 4개인데 상위 5개 중 2개가 관련이면 정밀도 2/5, 재현율 2/4다.

말을 더 풀어 보면

k는 위에서 몇 개까지 볼지다. 두 지표는 분모가 다르다.

비유의 경계 관련 문서 전체를 모르면 재현율을 정확히 계산하기 어렵다.

잠깐 가리고 떠올리기 · 이 개념의 역할은?

가져온 것 기준 / 필요한 것 기준 — 정밀도 = 가져온 것 중 맞는 비율, 재현율 = 필요한 것 중 찾은 비율

Precision@k = (상위 k 중 관련 조각 수) / k
Recall@k = (상위 k 중 관련 조각 수) / (전체 관련 조각 수)
숫자 예제. Precision@4 = 2/4 = 0.50. Recall@4 = 2/3 ≈ 0.67.
문장으로 읽기: 정밀도는 "가져온 것 중 쓸모 있는 비율", 재현율은 "쓸모 있는 것 중 가져온 비율". 1단계는 재현율, 2단계는 정밀도를 겨냥한다.
수식 3

Reciprocal Rank@k

RR@k = 1 / (첫 번째 관련 조각의 순위)
숫자 예제. 첫 관련 조각이 2위 → RR = 1/2 = 0.50. 1위였다면 1.0, 상위 k 안에 없으면 0.
문장으로 읽기: "쓸 만한 것이 얼마나 빨리 나오나". 하나만 찾으면 되는 질문에 맞는 지표.
수식 4

NDCG@k — 순위까지 반영

DCG@k = Σi=1..k reli / log2(i+1) ,   NDCG@k = DCG@k / IDCG@k
reli렐 아이i위 결과의 관련도 (여기서는 0 또는 1)log2(i+1)할인순위가 낮을수록 점수를 깎는 분모IDCG아이 디시지순위가 완벽했을 때의 DCG
숫자 예제. 할인 분모: 1위 log₂2=1, 2위 log₂3≈1.585, 3위 log₂4=2, 4위 log₂5≈2.322.
DCG = 0/1 + 1/1.585 + 1/2 + 0/2.322 = 0.631 + 0.5 = 1.131
이상적 순서 [✓,✓,✓,✗]의 IDCG = 1 + 0.631 + 0.5 = 2.131
NDCG@4 = 1.131 / 2.131 ≈ 0.53
문장으로 읽기: 관련 있는 것을 위쪽에 둘수록 점수가 높고, 완벽한 순서일 때 1이다.

자주 하는 오해

❌ "도구 호출에서 LLM이 함수를 직접 실행한다."
✅ LLM은 호출문을 글로 출력할 뿐입니다. 실행은 바깥의 프로그램이 하고 결과를 다시 넣어 줍니다.
❌ "에이전트 = LLM을 한 번 부르는 챗봇에 도구를 붙인 것."
✅ 핵심은 반복입니다. 결과를 보고 다음 행동을 스스로 정하는 루프가 있어야 에이전트입니다.
❌ "MCP와 A2A는 같은 종류의 표준이다."
✅ MCP는 모델과 도구·데이터 사이, A2A는 에이전트와 에이전트 사이의 약속입니다.

확인 퀴즈 3문항

답을 열기 전에 소리 내어 답해 봅니다.

Q1. 검색을 한 번에 cross-encoder로 하지 않고 bi-encoder → cross-encoder 두 단계로 나누는 이유는?
Cross-encoder는 질문과 조각을 한 쌍씩 함께 읽어야 해서 지식 베이스 전체에 돌리기엔 너무 느립니다. Bi-encoder는 조각 벡터를 미리 계산해 둘 수 있어 빠르게 후보를 추리고(재현율), 그 소수에만 정확한 cross-encoder를 씁니다(정밀도).
Q2. 관련 조각이 전체에 2개 있고 상위 3개 결과가 [✓, ✗, ✓]일 때 Precision@3, Recall@3, RR@3은?
Precision@3 = 2/3 ≈ 0.67, Recall@3 = 2/2 = 1.0, 첫 관련 조각이 1위이므로 RR@3 = 1.0입니다.
Q3. "곰 인형이 추워해요" 예시에서 에이전트가 온도를 바로 올리지 않고 먼저 온도를 조회한 이유를 ReAct 단계로 설명해 보자.
첫 관찰 단계에서 "원인이 방 온도일 수 있지만 현재 온도를 모른다"는 것을 정리했고, 그래서 계획이 "온도 확인"이 되었습니다. 조회 결과(65°F, 평균보다 5°F 낮음)를 다시 관찰한 뒤에야 "5°F 올리기"라는 다음 계획이 나옵니다. 모르는 것을 먼저 확인하는 것이 루프의 요점입니다.
