선호 튜닝

SFT를 마친 모델도 "곰 인형과 시간을 보내지 마세요" 같은 엉뚱한 답을 합니다. 정답을 일일이 써 주는 대신 "A가 B보다 낫다"는 신호로 모델을 사람의 선호에 맞추는 방법을 봅니다.

이 장을 마치면DPO가 무엇을 없앴는지 수식으로 읽을 수 있다

앞 조각 · 4장

4장의 SFT는 모범 답안 하나를 따라 배우게 한다. 하지만 두 답 중 더 나은 쪽을 고르는 정보도 쓰고 싶다.

지금 맞출 조각

선호를 점수나 비교 신호로 바꾸어 더 원하는 답을 내도록 조정한다.

다음 조각 · 6장

‘사람이 좋아하는 답’과 ‘수학 정답을 맞힌 답’은 다르다. 직접 확인할 수 있는 보상으로 확장한다.

  1. 1. 같은 질문의 답 두 개를 비교한다

    왜 필요한가 정답을 처음부터 쓰는 것보다 A가 B보다 낫다고 고르기 쉬운 경우가 있다.

  2. 2. 선호를 예측하는 채점 모델을 만든다

    왜 필요한가 사람이 매번 채점하기 어려워 점수를 대신 내는 모델을 학습한다.

  3. 3. 채점 신호로 답 생성 규칙을 갱신한다

    왜 필요한가 좋은 점수만 좇아 한 번에 크게 바뀌는 문제를 줄인다.

  4. 4. 다른 경로로 선호 쌍을 직접 학습한다

    왜 필요한가 DPO는 PPO 뒤의 필수 단계가 아니라, 별도 보상 모델을 두지 않는 대안이다.

화살표는 이해를 위한 연결입니다. 모두를 반드시 순서대로 적용하는 시스템 구성도는 아닙니다. 특히 DPO는 PPO의 대안 경로입니다.

같은 선호 데이터에서 출발해 두 길로 갈립니다.

생활 비유: 요리 대회 심사

왜 "비교"인가

레시피를 쓰기보다 맛을 비교하기가 쉽다

완벽한 요리의 레시피를 처음부터 쓰라면 어렵지만, 두 접시 중 어느 쪽이 나은지는 누구나 말할 수 있습니다. SFT는 모범 레시피를 요구하고, 선호 튜닝은 "이 접시가 저 접시보다 낫다"만 요구합니다.

RLHF와 DPO

심사위원을 길러 쓸까, 기록지를 바로 쓸까

RLHF: 사람의 비교 기록으로 심사위원(보상 모델)을 먼저 길러 놓고, 요리사가 새 요리를 낼 때마다 심사위원 점수를 받아 고쳐 나갑니다. DPO: 심사위원 없이, 요리사가 비교 기록지를 직접 보고 "이긴 접시처럼, 진 접시와는 다르게" 손을 고칩니다.

한계. 심사위원도 모델이라 속일 수 있습니다. 요리사가 맛이 아니라 심사위원의 버릇을 공략하면(reward hacking) 점수만 오릅니다. 그래서 "원래 실력에서 너무 벗어나지 말라"는 제약이 붙습니다.

핵심 개념 카드

필수 ①

왜 선호 튜닝이 필요한가

  • 생성(A를 처음부터 쓰기)보다 비교(A가 B보다 낫다)가 쉽다.
  • SFT는 데이터 분포에 민감해 "망치기" 쉽다.
  • SFT용 고품질 데이터는 구하기 어려워 확장이 안 된다.
  • SFT는 "하지 말아야 할 것"이라는 부정 신호를 직접 주지 못한다.
다만 모델이 이상하게 굴면 SFT 데이터 품질부터 의심해 보라는 신호이기도 합니다.
필수 ②

선호 데이터의 세 형태

한 문장으로선호 데이터 = 같은 질문에서 어떤 답이 더 나은지 표시하기

작은 예 A는 친절하고 정확한 답, B는 불친절한 답이라면 A 선호로 기록한다.

말을 더 풀어 보면

Pointwise는 답 하나의 점수, Pairwise는 두 답의 승패, Listwise는 여러 답의 순위다.

비유의 경계 선호 기준과 평가자가 다르면 라벨도 달라질 수 있다.

잠깐 가리고 떠올리기 · 이 개념의 역할은?

점수 / 두 답 비교 / 전체 순위 — 선호 데이터 = 같은 질문에서 어떤 답이 더 나은지 표시하기

형태예
Pointwise관측마다 점수: 0.4, 0.9, 0.1, 0.2
Pairwise둘씩 비교: 1 < 2, 1 > 3, 1 > 4, 2 > 3
Listwise전체 순위: 2 > 1 > 4 > 3

쌍 데이터 만드는 법. ① 같은 프롬프트에 답 두 개 생성(로그나 기준 분포의 입력 + SFT 모델·합성·고쳐쓰기로 출력). ② 승패 라벨: 사람 평가 또는 대리 지표(LLM 심판, BLEU, ROUGE). 이분법 또는 세밀한 척도.

필수 ④

한 문장으로RLHF의 보상 모델 = 사람의 선호를 흉내 내는 채점기

작은 예 사람이 A를 B보다 자주 선호했다면 A에 높은 점수를 주도록 배운다.

말을 더 풀어 보면

보충 ⑥

PPO — 조금씩만 바꾸기

한 문장으로PPO = 좋은 선택을 더 하게 하되 과한 갱신의 이득을 제한하기

작은 예 예상보다 좋은 답이면 그 답을 낼 확률을 높이는 방향으로 학습한다.

말을 더 풀어 보면

어드밴티지는 예상 대비 얼마나 좋았는지다. Clipping은 확률 비율을 이용해 과한 변화가 주는 학습 이득을 제한한다.

비유의 경계 PPO-Clip은 모든 확률 변화를 일정 범위 안에 강제로 가두는 보장은 아니다.

잠깐 가리고 떠올리기 · 이 개념의 역할은?

예상보다 좋았나 + 과하게 바뀌나 — PPO = 좋은 선택을 더 하게 하되 과한 갱신의 이득을 제한하기

Proximal Policy Optimization. 실제로는 보상 그 자체가 아니라 어드밴티지(보상 − 기준선)를 최대화합니다. 기준선은 가치 함수가 줍니다: 토큰 단위로 "이 정책을 따르면 받을 보상"을 예측하며, 정책과 함께 학습됩니다(GAE로 추정).

변형"조금씩"을 지키는 법
PPO-Clip새 정책과 옛 정책의 확률 비율을 잘라 목적 함수의 이득을 제한. 실제 확률 변화의 절대적인 상한은 아님
PPO-KL penalty두 정책 분포의 차이(KL)에 벌점. 요즘은 기준(base) 모델과의 KL을 씀
용어 주의: 슬라이드도 지적하듯, 이것은 "최대화"하는 목적 함수이지 손실이 아니고, 식의 r은 보상이 아니라 비율(ratio)입니다.
보충 ⑦

RL의 어려움과 Best-of-N

한 문장으로Best-of-N = 여러 답 중 채점 점수가 가장 높은 답 고르기

작은 예 답 4개를 생성해 2·7·4·5점을 받았다면 7점 답을 선택한다.

말을 더 풀어 보면

추론 시 선택은 학습과 다르다. 이 선택만으로 가중치가 바뀌지는 않는다.

비유의 경계 최고점이 실제 최고 품질이라는 보장은 없으며 생성 비용이 늘어난다.

잠깐 가리고 떠올리기 · 이 개념의 역할은?

여럿 만들고 최고점 선택 — Best-of-N = 여러 답 중 채점 점수가 가장 높은 답 고르기

어려움. 보상 모델을 따로 학습(2단계) · 하이퍼파라미터 많음 · 학습 불안정 · 지켜볼 지표가 불분명 · 생성의 다양성 필요 · 선호 튜닝에 꼭 RL이 필요한지 분명치 않음.

영화 보기0.8 ①
소풍 가기0.2 ②

Best-of-N. RL을 건너뛰고, SFT 모델로 답을 N개 만든 뒤 보상 모델 점수가 가장 높은 것을 고릅니다. 학습은 필요 없지만 매 요청마다 N배 생성이라 추론 비용이 큽니다.

말을 더 풀어 보면

공통 질문: “이 답을 더 자주 내게 하려면 무엇을 학습 신호로 쓸까?” 아래 네 방법을 모두 차례로 실행해야 하는 것은 아닙니다.

방법마다 사용하는 피드백의 차이
방법읽는 신호머릿속 장면다시 볼 곳
SFT질문 + 모범 답안“이렇게 답해”를 따라 쓰기4장 · SFT
PPO 기반 RLHF생성한 답의 보상과 가치 기준선채점 받고, 예상보다 좋았던 선택을 더 하기이 장 · PPO
기본 DPO선호된 답과 덜 선호된 답의 쌍승패 기록으로 상대 확률 고치기이 장 · DPO
원형 GRPO같은 질문에서 만든 답 묶음의 보상한 조 평균보다 잘했는지 비교하기6장 · GRPO

기억 문장은 첫 이해를 위한 요약입니다. 실제 학습에는 기준 모델, 손실식, 데이터 구성 등 아래의 상세 조건이 함께 필요합니다.

최소 수식 해부

수식 1

Bradley-Terry와 보상 모델 손실

P(yw ≻ yl) = erw / (erw + erl) = σ(rw − rl)
LRM = − log σ(rw − rl)
yw, yl와이 더블유, 와이 엘이긴(winner) 답과 진(loser) 답rw, rl알보상 모델이 각 답에 준 점수σ시그마 (시그모이드)아무 숫자를 0~1로 바꾸는 함수
문장으로 읽기: 이긴 답이 실제로 이길 확률은 두 점수의 차이로 정해진다. 그 확률이 낮으면 벌점.
숫자 예제. rw=0.8, rl=−2 → 차이 2.8 → σ(2.8) ≈ 0.943 → 손실 ≈ 0.059 (잘 맞힘).
반대로 rw=−2, rl=0.8 → σ(−2.8) ≈ 0.057 → 손실 ≈ 2.86 (크게 틀림).
수식 2

RLHF의 목적 함수

maxπ   E[ r(x, ŷ) − λ · KL( π(ŷ|x) ‖ πref(ŷ|x) ) ]
KL(P‖Q) = Σi pi log(pi/qi)
π파이지금 학습 중인 정책(LLM)r(x,y)알프롬프트 x에 대한 답 y의 보상 점수πref파이 레프기준 모델(SFT 모델), 고정KL케이엘두 분포가 얼마나 다른지λ람다"멀어지지 마" 항의 세기E[·]기댓값여러 프롬프트·답에 대한 평균
문장으로 읽기: 평균 보상을 높이되, 기준 모델과 달라진 만큼 감점한다.
PPO-KL 형태: LKLPEN = E[ ρ · Â − β · KL(πold ‖ πθ) ]. 원래는 직전 반복의 정책(old)과 비교했고, 요즘은 기준(ref) 모델과 비교한다.
수식 3

PPO-Clip

Lclip = E[ min( ρ · A , clip(ρ, 1−ε, 1+ε) · A ) ]
ρ = πnew(a|s) / πold(a|s)
ρ로 (비율)새 정책이 그 토큰에 준 확률 ÷ 옛 정책의 확률. 논문에서는 rtA에이 (어드밴티지)보상 − 기준선. 평소보다 얼마나 좋았나ε엡실론허용 변화 폭 (예: 0.2)
숫자 예제 (ε = 0.2).
ρ=1.5, A=+2 → min(3.0, 1.2×2=2.4) = 2.4. 좋은 행동이라도 확률을 20% 넘게 올린 몫은 인정하지 않는다.
ρ=0.5, A=−1 → min(−0.5, 0.8×(−1)=−0.8) = −0.8. 불리한 쪽으로는 더 비관적인 값을 쓴다.
수식 4

DPO 손실

LDPO = − log σ( β [ log π(yw|x)/πref(yw|x) − log π(yl|x)/πref(yl|x) ] )
π(yw|x)파이학습 중인 모델이 이긴 답에 주는 확률πref파이 레프기준 모델이 같은 답에 주는 확률log π/πref로그 비기준보다 얼마나 더 밀어주는가 = 숨은 "보상"
문장으로 읽기: 수식 1의 r 자리에 "기준 모델 대비 로그 확률 비"를 넣은 것. 이긴 답은 기준보다 더, 진 답은 기준보다 덜 나오게 한다.
유도 5단계(생략된 계산): PPO 목적 → 최적 정책 → "보상" 항 식별 → Bradley-Terry 대입 → DPO 손실. 논문 제목처럼 "언어 모델이 곧 보상 모델"이다.

자주 하는 오해

❌ "RLHF는 사람이 학습 내내 실시간으로 점수를 준다."
✅ 사람은 처음에 선호 데이터를 만들 때만 참여합니다. 강화학습 단계에서는 그 데이터로 학습한 보상 모델이 점수를 줍니다.
❌ "보상을 최대화하는 것이 목표의 전부다."
✅ KL 제약이 절반입니다. 제약이 없으면 보상 모델의 허점을 파고드는 이상한 답으로 무너집니다.
❌ "DPO는 RLHF보다 항상 낫다."
✅ 구현이 쉬운 것은 맞지만 성능 우열에는 합의가 없습니다. 과제와 구현 세부에 따라 달라집니다.
❌ "선호 튜닝은 모델에 새 지식을 넣는다."
✅ 이미 낼 수 있는 답들 중 어느 쪽을 더 내게 할지 조정합니다. 지식은 사전학습·SFT·검색의 몫입니다.

확인 퀴즈 3문항

답을 열기 전에 소리 내어 답해 봅니다.

Q1. 보상 모델이 이긴 답에 1.0, 진 답에 1.0을 줬다면 Bradley-Terry 확률과 손실은 얼마일까? 이 상황은 무엇을 뜻할까?
차이가 0이므로 σ(0) = 0.5, 손실은 −log 0.5 ≈ 0.69입니다. 보상 모델이 두 답을 전혀 구분하지 못하고 동전 던지기를 하고 있다는 뜻입니다.
Q2. PPO 기반 RLHF에 필요한 모델 4개는 무엇이고, DPO에서는 그중 무엇이 빠질까?
정책(학습되는 LLM), 가치 함수, 보상 모델, 기준(base) 모델입니다. DPO는 보상 모델과 가치 함수가 필요 없고 정책과 기준 모델만 씁니다.
Q3. Best-of-N과 DPO는 둘 다 RL을 피합니다. 비용이 발생하는 시점은 어떻게 다를까?
Best-of-N은 학습 비용이 없지만 요청마다 N개를 생성하므로 추론 때마다 비용이 듭니다. DPO는 학습 때 한 번 비용을 치르고, 추론은 평소와 같은 한 번 생성입니다.
