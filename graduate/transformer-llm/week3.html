🧠 1. LLM은 ‘다음 토큰 확률 기계’

Language Model은 토큰 시퀀스에 확률을 부여합니다. LLM은 이를 매우 큰 데이터·파라미터·연산 규모의 Transformer로 구현한 것입니다.

🏢 2. MoE · 거대한 회사에서 필요한 전문가만 호출

🧯 자주 헷갈리는 개념

MoE는 여러 LLM을 따로 호출하는 Ensemble인가?

보통은 아닙니다. 하나의 모델 내부에서 각 토큰의 FFN 계산을 여러 expert 중 일부로 routing하는 구조입니다.

Temperature를 낮추면 사실이 아닌 답이 없어지는가?

아닙니다. 출력 분포를 더 뾰족하게 만들 뿐, 모델이 가진 잘못된 지식이나 추론 오류를 고치지는 않습니다.

Top-k와 MoE의 Top-k는 같은 뜻인가?

“상위 k개를 선택한다”는 연산은 비슷하지만 대상이 다릅니다. Sampling의 Top-k는 다음 토큰 후보, MoE의 Top-k는 활성화할 expert 후보입니다.

Context Window가 늘면 기억력이 무한해지는가?

아닙니다. 입력 가능한 길이가 늘어날 뿐, 긴 문맥의 모든 정보를 동일하게 잘 활용하거나 대화 밖의 정보를 영구 기억한다는 뜻은 아닙니다.

KV Cache는 모델 파라미터를 저장하는가?

아닙니다. 각 요청의 과거 토큰에서 계산된 Attention Key와 Value 활성값을 저장합니다. 모델 가중치와 별도 메모리입니다.

Speculative Decoding은 작은 모델의 낮은 품질을 받아들이는가?

정확한 수락·재표본화 절차를 쓰면 목표 모델의 출력 분포를 보존하면서 속도를 높이는 것이 목적입니다.

✅ 연결 확인 퀴즈

Q1. MoE에서 총 파라미터와 활성 파라미터를 나눠 봐야 하는 이유는?

Router가 토큰마다 일부 expert만 선택하므로 전체 모델 크기와 실제 한 토큰 계산량이 서로 다를 수 있기 때문입니다.

Q2. Greedy와 Sampling의 가장 큰 차이는?

Greedy는 항상 확률 1등을 고르고 Sampling은 확률분포에서 무작위로 뽑아 다양성을 허용합니다.

Q3. Top-p가 Top-k보다 후보 수를 유동적으로 정하는 이유는?

고정 개수가 아니라 누적확률 기준을 사용하므로 모델이 확신할 때는 적은 후보, 불확실할 때는 더 많은 후보가 남습니다.

Q4. KV Cache의 계산-메모리 trade-off는?

과거 K·V 재계산을 줄여 생성은 빨라지지만 입력 길이·배치·사용자 수에 비례해 메모리 사용이 커집니다.

Q5. PagedAttention과 Speculative Decoding은 같은 병목을 해결하는가?

아닙니다. PagedAttention은 KV 메모리 배치와 낭비를 개선하고, Speculative Decoding은 순차적인 토큰 생성 지연을 줄입니다.
